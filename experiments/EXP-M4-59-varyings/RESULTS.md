# EXP-M4-59: general vertex/fragment linkage

T8132 M4, 2026-09-05. Standalone Mesa/DRM-shim tests and own-source Metal
command/data captures. Both live Mesa API shader mains are generated by the
semantic compiler. No proprietary Apple binary was disassembled/decompiled;
only source-correlated scalar export/iterator patterns in the authored probe
mains and command/data records were examined. Opaque launchers were compared
as byte strings and copied whole; no launcher algorithm was reproduced.

## Interface and command data

A 32-entry component-mask layout maps VAR0..VAR31 to dense scalar slots.
Position occupies export slots 0..3. Up to twelve user scalars follow, with
fragment variants compiled and cached against the actual producing VS map.
The layout supports component holes, unused producer outputs, and constant
array offsets. Missing producer components and unsupported types/modes fail
compilation. Twelve is the current retained-publication compiler limit, not a
hardware maximum.

The native three/nine/twelve probes establish:

- Context bind0 +0x44: 3/9/12 user scalar count. This field was misidentified
  as a G16 class byte and hardcoded to 3, truncating later vertex data.
- VDM vertex class: 0x0707/0x0d0d/0x1010, including four position scalars.
- PPP +0x2c: 7/13/16, likewise including position.
- PPP +0x04 bits16+: CF binding count (including the 1/W binding).
- PPP +0x08: CF table offset from USC base.
- PPP +0x18: coefficient allocation group, `user_components / 8`.
  Independent standalone seven/eight-component tests cover the transition.
- CF header: low byte user+1 slots, next byte user+1 coefficient registers.
  The extra slot is 1/W. The public CF descriptor layout applies on T8132.

The driver now authors its table at USC+0x200040, in the caller-owned graphics
data page, and derives all these fields from the linked interface. The table
contains the 1/W binding and runs of up to four user components. Runtime
readback instrumentation confirmed the intended table and PPP words reached
the submission. That temporary shim instrumentation was removed.

## Perspective behavior

The initial native perspective descriptor model (shade 7), ordinary ITER,
then unconditional multiply by reciprocal interpolated 1/W passed W=1 but
failed a nine-component unequal-W test. A six-frame component-picker probe
isolated the problem: components constant across each primitive acquired an
extra factor of W, while nonconstant components were correct. For example,
vertex color B=0.375 became approximately 0.234375 at W=0.625 and 0.515625 at
W=1.375. Changing the W iterator's byte6 field from 0 to 4 did not change the
result in this configuration. The complete native perspective/constant
iterator contract remains unresolved.

The first workaround multiplied user exports by reciprocal clip W in the VS,
used linear shade-3 CF bindings, and divided by interpolated 1/W in the FS.
It passed the initial unequal-W image but corrupted attributes when homogeneous
clipping created vertices. It is superseded by the final implementation below.

The authored `nine.metal` fragment main contains a coefficient-aware projective
multiply: operation selector 7, eight bytes, six-bit GPR operands and an explicit
coefficient index in byte 5. Its coefficient operand matches the ITER slot.
Mesa models this as `FMUL_PROJECT` / `FLOAT2_PROJECT`. The VS exports unprojected
values, the driver requests native shade-7 perspective coefficients, and the FS
uses the projective multiply with reciprocal interpolated 1/W. This handles both
primitive-constant coefficients and attributes created by hardware clipping.
Ordinary ITER/FRCP controls suffice; exploratory extra W-path bits were removed.

See [clipping follow-up](CLIPPING.md) for the source-correlated evidence and
final validation. The earlier ordinary-multiply interpretation in EXP-M4-56
and the predivision workaround above are not the current compiler model.

## Opaque runtime capacity

Once all linkage state was corrected, twelve components still produced zero
blue with the old four-buffer VS launcher. Installing the complete 0xc0-byte
VS launcher from `twelve.pkl.gz` fixed all colors. The unchanged EXP-M4-58 FS
launcher remains the second 0xc0 bytes. The resulting external runtime blob is:

`tmp/agx-apple9/render_buffers_varyings12_launch.bin`

SHA-256 `0d7c5eac10ecbd282c96f04785b3d7475274f4cdf8f2b26ed2ae1a4258fb3f7d`.

`extract_launcher.py` reproduces it from the trusted twelve capture and the
old four-buffer blob. The old blob is retained unchanged. The production
compiler contains no captured shader body, fixed publication assignments,
or replay-specific sequences. Interfaces larger than four components use the
larger external launcher even when they have no buffer arguments.

## Validation

Permanent GLSL tests and an independent CPU checker are under
`mesa-m1n1-shim/src/asahi/drm-shim/scenes/varyings/`. Raw attachments and reports
are in `tmp/apple9-varyings-work/final-*`. Each 512x512 quad covers 98,304 pixels (131,072 when clipped);
indexed cases reverse triangle order. All paired attachments are identical.
See `VALIDATION.json` for the collected reports. Compiler tests cover sparse
locations/components, constant arrays, missing outputs, producer-dependent FS
indices and 0/12/13-component capacity boundaries.

The failed exploratory changes to register allocation, publication copies,
export completion hints, CF grouping/address placement, and iterator mode were
reverted. Flat/integer and other interpolation modes remain future work.

Final verification: 190 compiler tests and 24 standalone hardware frames pass.
The clipped unequal-W case has exact coverage and at most one color byte of
rounding error. Quad, depth cube, 100 triangles, and a two-frame full island
regression pass their independent color/depth checks. The island uses all
3,541 attribute vertices and 2,476 triangles, with zero color/order differences
and maximum depth error 8.669431522667637e-7 in the checked view.

The subsequent clipping gate passes all nine varying modes (18 frames), 16
1024-square sunset frames, and two basic-triangle frames: 36 final hardware
renders. All 191 compiler tests pass. The larger-render gate also uses the
separate m1n1 tilemap/heap-metadata fix described in CLIPPING.md; that change
belongs to the m1n1 repository, not Mesa.
